MET Art Gallery Explorer

An interactive museum dashboard for exploring artworks from the Metropolitan Museum of Art through a FastAPI backend, MySQL database, and Streamlit frontend. This project demonstrates the integration of modern web technologies to create a seamless user experience for exploring art collections. I used RestAPI's to first connect to the METs public collection, then built a FastAPI backend to serve the data, and finally created a Streamlit dashboard to visualize and explore the artworks. The project is containerized with Docker and structured for deployment on AWS.

The MET Art Gallery Explorer allows users to filter artworks by artist and century, view metadata and images, and visualize trends in the collection. It showcases full-stack software engineering skills across backend development, database design, data visualization, and cloud deployment.

Overview

This project turns the MET Museum's public collection into a browsable web experience. It combines a Streamlit dashboard, a FastAPI service layer, and a MySQL database so users can filter artworks, inspect metadata, and visualize patterns in the collection.

Key Features

Interactive Dashboard

Built in Streamlit with filtering, charts, and a gallery view for exploring a curated artwork dataset.

Artwork Discovery

Browse artworks by artist, century, department, title, and image, with details surfaced through a clean API response.

FastAPI Backend

A lightweight REST API provides health checks and artwork retrieval endpoints for the frontend.

Persistent Data Model

MySQL stores artists and artworks in a structured schema that supports joins and scalable querying.

Data Visualization

Plotly charts make it easier to spot trends across time periods, artists, and departments.

Deployment Ready

The project is containerized and structured for AWS deployment using ECS, EC2, and RDS.

Architecture

The application follows a simple service-oriented structure with clear boundaries between storage, API, and user interface.

Dashboard (Streamlit) sends HTTP requests to API (FastAPI), which runs SQL queries against MySQL and returns JSON back to the dashboard.

Database

MySQL stores artist records and artwork metadata including title, year, century, department, and image URL.

API

FastAPI exposes endpoints like GET /health and GET /artworks for lightweight data access.

Dashboard

Streamlit presents filters, charts, and a gallery interface for browsing the returned collection.

Tech Stack

Python 3.8+, FastAPI, Streamlit, MySQL, Docker, Docker Compose, Plotly, and AWS infrastructure tooling.

Local Setup

  1. Clone the repository and create a Python virtual environment.
  2. Install dependencies from requirements.txt.
  3. Create a MySQL database named met_art.
  4. Set database environment variables such as DB_HOST, DB_USER, DB_PASSWORD, DB_NAME, and DB_PORT.
  5. Initialize the database with python scripts/bootstrap_db.py.
  6. Start the API with API_PORT=8001 python scripts/start_api.py.
  7. Launch the dashboard with streamlit run dashboard/dashboard.py.

Usage

Once running, the dashboard allows users to browse artworks, filter by artist or century, and inspect visual summaries of the collection. The API also supports direct endpoint access for health checks and artwork retrieval.

Docker and Deployment

The app includes separate Dockerfiles for the API and dashboard, along with Docker Compose configurations for local development, AWS-oriented setups, and EC2-based deployment.

For cloud deployment, the intended path is AWS ECS for services, RDS for MySQL storage, and ECR for container images. The deployment flow includes building images, pushing them to ECR, and updating ECS task definitions with the correct database connection variables.

What This Project Demonstrates

This project highlights full-stack software engineering across backend APIs, databases, data visualization, containerization, and deployment. It also shows how public cultural datasets can be turned into a more accessible and exploratory user experience.
